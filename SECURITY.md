# 安全报告 / Security reporting

潜在漏洞、私钥或凭据泄露不应通过公开 Issue 或 PR 披露。优先在受影响仓库的 Security → Advisories → Report a vulnerability 使用 GitHub 私密漏洞报告（如已启用）。如该入口不可用，请先用不包含漏洞细节的 Issue 请求维护者提供私密联系渠道；本项目尚未公布专用安全邮箱或响应 SLA，不要猜测地址或上传敏感附件。

报告中准备受影响版本/提交、环境、影响范围和最小复现。只在授权范围内测试，脱敏个人信息和凭据。若凭据已公开，立即在其所属系统撤销并轮换，不只删除消息。修复支持范围和可用版本以各项目实际发布说明为准。

Do not disclose exploitable details, private keys or credentials in public issues or pull requests. Prefer the affected repository's GitHub private vulnerability reporting entry if enabled. Otherwise request a private contact channel without including exploit details. No dedicated security email or response SLA is currently published. Prepare affected versions, environment, impact and a minimal authorized reproduction. Revoke and rotate exposed credentials at their source.
